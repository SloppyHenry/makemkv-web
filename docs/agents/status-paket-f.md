## Preset values and rationale
Sources: HandBrake documentation "Adjust Quality" (recommended RF ranges: SD 18–22, 720p 19–23, 1080p 20–24, 2160p 22–28 for x264/x265; SVT-AV1: SD 22–32, 720p/1080p 25–35, 2160p 25–40; the encoders' scales are **not** directly comparable), x265 documentation "Presets and tunes" (grain: aq-mode 0, cutree 0, psy-rd 4.0, psy-rdoq 10, sao 0; animation: psy-rd 0.4, aq-strength 0.4, deblock 1:1, bframes +2), SVT-AV1 `Docs/Ffmpeg.md` (CRF 1–70, 30 as a start for 1080p, preset 0–13, 4–6 for home use, `film-grain` 8 for live action, 10-bit recommended), ffmpeg wiki (x265 CRF 28 ≈ x264 CRF 23).
| Preset | Values | Rationale |
|---|---|---|
| DVD optimal | x265 10-bit, RF 19, slow, aq-mode=3:no-sao=1, deinterlace auto, light denoise (hqdn3d 2:1:2:3), copy audio | SD range 18–22; MPEG-2 noise otherwise costs bits; many DVDs are interlaced/telecined (idet → bwdif or IVTC) |
| Blu-ray optimal | x265 10-bit, RF 20, slow, aq-mode=3:no-sao=1, copy audio | 1080p range 20–24; previous default (formerly RF 21) |
| Blu-ray Animation | x265 10-bit, RF 22, slow, tune animation, no own aq parameters | flat areas tolerate a higher RF; own aq parameters would override the tune |
| Film with heavy grain | x265 10-bit, RF 19, slow, tune grain | the tune sets aq-mode 0/psy-rd 4/psy-rdoq 10/sao 0; grain costs bits, hence a lower RF; no aq-mode=3 |
| UHD / keep HDR | x265 10-bit, RF 22, medium, aq-mode=3, pass HDR10 through | 2160p range 22–28; `slow` would be very slow at 4K; mastering display/MaxCLL/BT.2020-PQ taken from the source; Dolby Vision is lost (HDR10 base stays) |
| Small & fast | x265 10-bit, RF 26, faster, ≤ 720p, deinterlace auto, AAC stereo 160 kb/s | about 4× faster than slow and much smaller; AAC plays everywhere |
Quality scale per codec (slider "smaller ← → better", 0–100): x265 RF 30→14, x264 CRF 28→12, SVT-AV1 CRF 45→18, hardware QP 34→16. The same slider position = roughly the same perception (x265 RF 20 ≙ x264 CRF 18 ≙ SVT-AV1 CRF 28 ≙ hardware QP 23). This is a reasoned approximation, not a measurement: the test encode (two short excerpts) is meant to check it in individual cases later. Word markers: from 80 "optisch verlustfrei", from 56 "hoch", from 33 "ausgewogen", from 12 "klein".

## Interfaces offered
**Settings schema v2** (`cfg`, everywhere the five fields used to be): see the head of `app/convert_schema.py`. Sections `video`, `quality`, `picture`, `sound` (not `audio`!), `subs`, `origin` (ID of the preset); above them the **mirror** of the old fields `rf, preset, tune, extra, audio` (so old interfaces/machines do not read anything wrong).
**API** (all `GET/POST /api/convert/…`; not in the proxy, the browser calls its own machine):
- `GET /meta` → codecs (with `available`), scales, word markers, `presets` (bundled + own, each `{id, name, desc, builtin, cfg}`), `defaults` per disc type `{bluray|dvd|uhd: {id, cfg}}`, `caps`, `stats`.
- `POST /normalize {cfg}` → `{cfg (v2 complete), v1_compatible, summary, command}`; `POST /translate {cfg, files:[{to:"x264"}]}` → switch codec with the same perception level.
- `POST /estimate {cfg, paths?:[…], files?:[{size,dur,w,h,fps,audio}]}` → `{in_bytes, out_bytes, samples, nodes:[{name, local, ok, reason, secs, samples, cores, load}]}` (without files: sample film 24 GB/2 h). `ok:false` + `reason` = grey out.
- `POST /probe {path, cfg}` → `{id}` (encode 2 × 25 s, one job at a time, with nice), `GET /probe/{id}` → `{status: running|done|error, pct, text, error, result:{out_bytes, in_bytes, secs_here, before, after}}` (`before`/`after` = still images as `data:image/jpeg`), `POST /probe/{id}/cancel`.
- `POST /presets {name, desc, cfg}`, `PATCH /presets/{id}`, `DELETE /presets/{id}`, `POST /defaults {kind, preset}`; `GET /stats`.
- `POST /start {target:"local"|<machine>, paths, convert:cfg, takeover_from?}` → like `/api/library/convert` (`{started, skipped}`); foreign machines only if `peer_ok` (old version/missing encoder → 409 with a reason). **The interface should use this endpoint from now on instead of `/api/peer/<name>/library/convert`.**
- `GET /api/library` additionally: per file `kind` (`sd|hd|uhd`), `est {preset, bytes, samples, issue}`, `info.{fps,bitrate,alist,slist,chapters,hdr_fmt,dovi,interlaced,abytes}`; `summary {count, bytes, orig_count, orig_bytes, save_bytes, free}`.
- Settings: namespace `convert` = `{presets:{id:{name,desc,cfg}}, default_for:{bluray|dvd|uhd: id}}`; `conv_parallel`, `conv_segments` stay in `general` (agreed with PB: my section `convert` delivers both in `collect()`: `{general:{conv_parallel, conv_segments}, convert:{…}}`). The old flat `presets.bluray/dvd` stay the **authoritative** default per disc type (old interfaces keep writing them); `default_for` only names the chosen preset and writes it into the flat fields.
- Capabilities in `/api/state` → `capabilities`: `encoders` (list of ffmpeg names, tested) and `convert {schema:2, codecs:[x265,x264,svtav1,hw,copy], hw:[…], hw10:[…], filters:[…], audio:[…], cores, speed:{codec: frames/s per core}}`.
**Frontend (after approval):** `import { mountConvertEditor, getDefaultConfig, cvSummary } from './convert-editor.js'`
- `const ed = mountConvertEditor(el, value, {target, onChange, mode, discKind, files})`
  - `value`: settings v1 **or** v2 (checked/migrated; `null` = default of the `discKind`), the field `convert` (on/off) is passed through unchanged, the switch stays with the panel (PA).
  - `target`: name of the machine for capabilities/forecast (`''` = this one), optional; `files`: optional sample files `[{path}]` or `[{size,dur,w,h,fps,audio}]` for the forecast; `mode`: `'full'` (cards, levels, forecast) | `'compact'` (row of cards + summary, "Anpassen" opens; for the title list) | `'side'` (side panel in the library).
  - `onChange(cfg)` receives the complete v2 settings (with the mirror of the old fields, so also usable for `POST /api/rip`); returns `{get(), set(cfg), destroy()}`.
- `getDefaultConfig(discKind)` (async, from `/api/convert/meta`), `cvSummary(cfg)` (short text).
- **Library actions (announcement, backward compatible):** `registerLibraryAction({id, label, icon, primary?, when(files, ctx), run(files, ctx)})`. `files` = array of the affected files (`{path,size,mtime,state,info,job,locked,kind,est}`), `ctx = {where:'row'|'detail'|'bar'|'folder', folder?}` (the second argument is new and optional). `when` is called with (a) **one** file (row/detail), (b) the **selection** (selection bar, ≥ 1 file), (c) **all files of a folder** (`where:'folder'`). An action meant for a single file checks `files.length === 1` and then does not appear in the bar. `primary: true` stays: click on the file name (only for exactly one file). The library shows actions with `when(selection)===true` as buttons in the bar.
